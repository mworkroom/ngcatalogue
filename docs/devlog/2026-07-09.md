# 2026-07-09 ngcatalogue Development Log

## Work Summary

iPhone 홈 화면에서 센터 주소는 `/center/`로 분리되지만 관리자 주소가 여전히 루트 `https://price.nangok.app/`로 열리는 문제를 조사했다. 배포된 `/admin/` HTML과 관리자 manifest 자체는 정상으로 확인되었고, 관리자만 Google OAuth 복귀 흐름을 거치면서 실제 문서 경로가 다시 해시 또는 루트 기준으로 흐를 수 있는 점을 원인 후보로 좁혔다.

## Work Completed

* 관리자 Google 로그인 시작 시 OAuth `redirectTo`가 현재 해시 주소나 루트가 아니라 실제 관리자 문서 경로인 `/admin/`을 사용하도록 변경했다.
* 관리자 로그인 전 `sessionStorage`에 저장하는 복귀 경로도 `#/admin` 대신 `/admin/` 실제 경로가 되도록 바꿨다.
* OAuth callback 뒤 현재 경로가 루트로 돌아와 있으면 `/admin/`으로 다시 이동하고, 이미 `/admin/`이면 callback query/hash만 정리하도록 복귀 로직을 수정했다.
* 서비스워커 캐시 버전을 `atomy-price-v5`로 올리고, navigation fetch 실패 시 `/admin/` 요청은 관리자 HTML 캐시, `/center/` 요청은 센터 HTML 캐시를 사용하도록 fallback을 분리했다.
* README의 route 설명을 현재 custom domain 구조에 맞춰 `/`, `/center/`, `/admin/` 기준으로 갱신했다.
* Supabase Google OAuth 설정 문서에 `https://price.nangok.app/admin/`을 Allowed Redirect URL로 별도 등록해야 한다는 내용을 추가했다.
* `npm.cmd run build`로 TypeScript와 Vite 프로덕션 빌드를 확인했다.
* 빌드 산출물의 `dist/admin/index.html`, `dist/center/index.html`, `dist/sw.js`에서 관리자/센터 manifest와 새 서비스워커 캐시 버전이 반영된 것을 확인했다.

## Decisions

배포된 `/admin/` HTML은 200 응답으로 정상 제공되고 `manifest-admin.webmanifest`도 `start_url`, `scope`, `id`가 모두 `/admin/`으로 되어 있었다. 따라서 정적 파일 충돌보다는 관리자만 갖고 있는 OAuth 복귀 흐름을 우선 수정하기로 했다.

iPhone 홈 화면 추가는 해시 뒤 경로를 독립된 문서 주소로 보지 않을 수 있으므로, 관리자 로그인 후에도 주소가 `/#/admin` 형태로 남지 않게 실제 `/admin/` 경로를 유지하는 방식을 선택했다. 센터는 OAuth가 없어 같은 문제가 나타나지 않았던 것으로 판단했다.

서비스워커 fallback도 함께 바꿨다. 네트워크가 실패했을 때 모든 navigation을 루트 `index.html`로 돌리면 `/admin/` 홈 아이콘에서도 루트 문서가 내려올 수 있으므로, 모드별 HTML 엔트리를 캐시 fallback으로 분리하는 편이 안전하다.

## Current Status

로컬 코드는 관리자 OAuth 복귀 경로를 `/admin/`로 유지하도록 수정되었다. 프로덕션 빌드는 성공했고, 빌드 결과물에서도 관리자와 센터 엔트리가 각각의 manifest를 참조한다.

실제 iPhone 검증은 배포 후 다시 해야 한다. 특히 Supabase Dashboard의 Google OAuth Allowed Redirect URL에 `https://price.nangok.app/admin/`이 없으면, 코드 수정만으로는 OAuth 제공자가 callback을 루트로 되돌리는 문제를 완전히 막을 수 없다.
